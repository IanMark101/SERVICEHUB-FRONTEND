# Marketplace locations and compact inboxes

Aligned October 16, 2026. CURRENT_SYSTEM.md is the shared behavior reference.

Every physical provider service and seeker public request selects one Discovery location. Search and map choose the same point; changing physical arrangements keeps it. No provider travel radius or fixed travel rejection exists. The browsing circle filters nearby physical results and supports 0.5–30 km in 0.1 km increments.

Providers accepting visitors add private workplace directions, not another map pin. Public requests do not collect a private job address at posting. During booking, Provider visits uses the seeker's actual private job location and Seeker visits uses the provider's saved venue. Eligible online/remote forms expose no location field, distance or marker and bypass the radius.

Current create/edit forms have no exact-public-pin checkbox and save approximate discovery. Legacy provider public-pin consent remains compatible in the API. Profile locality, search preferences and private booking addresses are independent.

Offers Received and Incoming Requests retain compact loading/error/empty states, searchable paginated rows, expandable work details and existing permission/payment/busy checks. Error feedback keeps red semantics in both workspaces. Accepting paid work does not start a job.
